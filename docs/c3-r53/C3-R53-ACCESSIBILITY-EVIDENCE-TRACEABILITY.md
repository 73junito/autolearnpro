# C3-R53 — Accessibility evidence manifest and release-gate traceability

**Authority:** development/testing only. **Production publication, Cloudflare Workers deployment, hosted Supabase migrations, DNS changes, signing authority, and real automotive models remain HOLD.**

## Source manifest

`accessibility-evidence-manifest.json` is versioned source evidence describing the two isolated synthetic-model pages, five mandatory automated acceptance families, Chromium/Firefox/WebKit standard browser coverage, and a separate **strict rendered Linux Firefox Mesa/Xvfb** mode. It explicitly records unresolved NVDA, VoiceOver, TalkBack, high-contrast, screen magnification, zoom, and error-recovery manual acceptance checks as `NOT_TESTED`. These claims must not be changed to `PASS` without separately reviewed, real manual evidence and authorization.

`infrastructure/scripts/c3-r53-accessibility-evidence.mjs --check` denies missing or changed tests, altered browser scope, false manual acceptance, or weakening `releaseStatus: HOLD`. Negative Node tests exercise omissions, skipped/failed browser tests, axe findings, missing rendered states, and forged certification/release claims.

## GitHub CI evidence report

The protected Foundation/Academic job now runs the same existing Playwright standard and strict Firefox suites with **both** a readable console reporter and a JSON result file stored under `_local/`. Once both complete, the fail-closed R53 assembler validates:
- **36 required test/browser/surface evidence entries:** 30 from five test families on two pages across three browsers, plus six independent strict Firefox rendered acceptance entries
- Required statuses `passed`, never skipped, failed, or flaky; complete expected audit states
- Zero axe WCAG A/AA violations in all required states, including strict Firefox rendered states
- SHA-256 digests of every referenced test source, the manifest, and the GitHub commit ID
- Every manual acceptance requirement still `NOT_TESTED`; `certification: NOT_CERTIFIED` and `releaseStatus: HOLD`

The assembler rejects missing or duplicated entries. If validation passes, `_local/r53-accessibility-evidence.json` is published as a **short-retention GitHub Actions test artifact**, not deployed to a website or database. The artifact is tied to the exact workflow run; raw Playwright logs remain available in the Actions run. A successful automatic artifact **is not WCAG certification** or manual screen-reader evidence.

GitHub workflow uses `actions/upload-artifact@v4` in the existing restricted, read-only CI job after validation, with a seven-day retention. This does not grant publishing, change DNS, connect to hosted Supabase, or authorize Cloudflare Workers deployment.

## Security and limitations

The report is deterministic given the test outputs, pinned manifest and commit ID; it contains no user information or timestamps generated by the assembler. It validates reported test outcomes, but is not a cryptographic attestation by independent auditors. Standard Linux headless Firefox may fail closed for WebGL and that mode is not certified as rendering; only the independent strict Mesa/Xvfb evidence asserts actual Firefox rendering. No actual assistive technology testing has been performed through this automation.
