## 5. Phase D — proposed integration

### 5.1 Two prerequisites that are easy to miss

**(a) The `.gitignore` negation is mandatory, and it is verified.** The tracked-in-HEAD rule `build/` matches
`infrastructure/c3/build/m`**`at any depth`**. In an isolated throwaway repo:

```
A) rules build/ + node_modules/ only:  .gitignore:1:build/   infrastructure/c3/build/m.mjs     <- ignored
B) after adding !infrastructure/c3/build/:  (no output)                                        <- not ignored
   node_modules/ still matched by .gitignore:3
```

Without the worktree's `.gitignore` modification, the entire C3 build tooling package is **invisible to Git** and
could never be committed — which is very likely why it is untracked today. The change also does not weaken
`node_modules/` exclusion at any depth.

**(b) The lockfile must be the reviewed one.** HEAD's `package-lock.json` (`2b756711…`) predates the catalog
workspace; the reviewed lockfile (`f805b6f7…`) registers `apps/catalog` with `vite 7.3.7` / `three 0.180.0` and 1,127
inserted lines with zero deletions. Committing `apps/catalog/package.json` without it produces an inconsistent tree,
and `npm ci` would then fail on the lockfile mismatch rather than install.

### 6.2 Proposed policy, for a future milestone

1. **Required explicit destination** for every driver that writes a report — the shape of `R36H3_OUT`: no default, and
   a mistyped variable named in the error.
2. **Exclusive creation** (`flag: 'wx'`) for every report file, so an existing reviewed artefact is refused, never
   truncated.
3. **Per-run ownership**: a run writes into `docs/c3-r3X/runs/<run-name>/` (flat, validated name) or an owned
   temporary directory, and nowhere else — the same containment and symlink checks as the gate.
4. **Cleanup scoped to the run**: remove only what the run created, only beneath a root it owns.
5. **A summary manifest generated by aggregation over run directories**, so the "one canonical file" problem
   disappears instead of being guarded around.

Not implemented here: this milestone is read-only, and rewriting ten drivers plus their saved evidence is an
implementation milestone with its own review. Historical records are untouched, and the destroyed `a9c39fd3…` bytes
are not fabricated back.

never be cited as clean-checkout evidence.**
